# 브릭 크롤 (Brick Crawl)

**벽돌깨기 + 턴제 전투 + 덱빌딩 로그라이크.** 움직이는 조준선에 타이밍을 맞춰 구슬을 쏘고, 내려오는 성벽을 깎아 천장까지 길을 내야 위쪽의 몬스터를 때릴 수 있다.

- 바로 플레이: **https://brick-crawl.pages.dev**
- 빌드 단계 없음, 외부 의존성 없음. 폴더를 내려받아 `index.html`을 열면(`file://`) 오프라인에서도 돈다.
- 라이선스: [MIT](LICENSE)

## 플레이 방법

| 동작 | 입력 |
|---|---|
| 구슬 발사 | 벽돌판 탭/클릭, `Space`, `Enter` |
| 메뉴(일시정지) | 오른쪽 위 `II` 버튼, `P`, `Esc` |

조준선은 스스로 좌우로 왕복한다. 플레이어는 **언제 누를지**만 정한다.
탭을 바꾸거나 창을 내리면 자동으로 일시정지된다.

진행은 브라우저 `localStorage`에 자동 저장된다(노드 진입, 전투 승리, 보상 선택, 상점 구매 시점).
전투 도중에 나가면 그 전투를 처음부터 다시 한다.

## 게임 규칙 한눈에 보기

> 전체 규칙과 수치는 [`docs/GAME_DESIGN.md`](docs/GAME_DESIGN.md)가 기준이다.

**화면**: 위는 전투(왼쪽 기사, 오른쪽 몬스터와 다음 행동 예고), 아래는 벽돌판. 맨 위 굵은 선이 천장, 중간 점선이 붕괴선이다.

**한 턴**
1. 조준선 타이밍에 맞춰 이번 구슬을 쏜다.
2. 구슬은 벽돌을 부숴도 튕긴다. **천장에 닿으면** 공격력만큼 몬스터를 때린다(구슬당 최대 3회).
3. 몬스터가 예고한 행동을 한다. 2턴마다 성벽이 한 줄 내려온다.
4. 붕괴선을 넘은 벽돌은 기사에게 피해를 준다.

**성장**: 공격력·방어도는 전투마다 초기화된다. 원정 동안 쌓이는 것은 **구슬(덱)**과 **유물**뿐이다. 숫자를 키우는 게임이 아니라 도구가 늘어나는 게임이다.

| 구분 | 내용 |
|---|---|
| 벽돌 | 성벽, ⚔ 공격, 🛡 방어, ♥ 체력, 독, 돌(보스 소환) |
| 구슬 | 기본, 폭탄, 송곳, 방패, 분열, 독, 묵직한 |
| 유물 | 천장 연타, 반격, 해독, 집중, 지지대, 수확, 구급상자 |
| 노드 | 전투, 정예, 휴식, 상점, 보스 |

원정은 세션 단위로 진행한다. 세션마다 3갈래 × 4칸짜리 갈림길 지도가 있고, 끝에 보스가 있다.

## 사운드

음원 파일 없이 브라우저(Web Audio)에서 칩튠 소리를 즉석으로 만든다. 오프라인·`file://`에서도 그대로 나온다.

- **BGM 3곡**: 메인·지도(느긋한 곡), 일반 전투(경쾌한 곡), 보스전(빠르고 낮은 곡).
- **구슬별 손맛**: 구슬마다 벽돌에 부딪는 소리와 천장을 치는 소리가 다르다. 같은 구슬이 벽돌을 연달아 맞히면 소리가 반음씩 올라간다(콤보).
- **장면 효과음**: 보스 등장·분노, 폭탄 폭발, 몬스터 타격·쓰러짐, 기사 피격, 성벽 하강·붕괴, 승리·패배, 상점(문 종·동전), 휴식(모닥불·회복).
- 브라우저 정책상 첫 탭(또는 키 입력)부터 소리가 난다. 메인 화면과 메뉴에서 **음악**과 **효과음**을 따로 끌 수 있고, 설정은 저장된다.

## 닉네임과 랭킹

처음 메인 화면에 들어오면 **임의 닉네임**이 정해진다. 맛·감각, 성격, 사물에서 3음절 단어를 하나씩 뽑아 일부러 어울리지 않게 조합한다(예: `바삭한 우울한 냉장고`, `뜨거운 수줍은 청바지`. 약 15만 가지). 닉네임은 그 브라우저에 저장되고 바꿀 수 없다.

원정이 끝나면(쓰러짐, 포기, 저장된 원정 덮어쓰기) 그 원정에서 돌파한 칸을 기록 서버에 올린다. 메인 화면에는 상위 3명과 내 순위가, `랭킹 전체 보기`에는 상위 10명이 나온다. 같은 기록이면 먼저 세운 쪽이 위다.

- 오프라인이거나 서버가 응답하지 않아도 게임은 그대로 돈다. 못 보낸 기록은 다음에 메인 화면에 왔을 때 다시 보낸다.
- 로그인이 없는 공개 API라 기록 조작을 완전히 막을 수는 없다. 지금은 형식과 범위만 검사한다. 시드 RNG가 들어오면(작업 01) 재현 검증으로 강화할 수 있다.

## 로컬에서 실행

**그냥 열기**: 저장소를 받아 `index.html`을 브라우저로 연다.
```bash
git clone https://github.com/jinikjang88/brick-crawl.git
cd brick-crawl
# index.html을 더블클릭하거나 브라우저로 드래그
```
`index.html`만 따로 옮기면 `css/`·`js/`를 못 찾는다. 폴더째로 둔다.

**로컬 서버로 열기**(선택): 아무 정적 서버나 된다.
```bash
python -m http.server 8000      # 또는 npx serve .
# http://localhost:8000
```

**필요한 것**: 최신 브라우저 하나. 시뮬레이터와 문법 검사에만 Node.js 18 이상이 필요하다.

**기록 서버까지 로컬에서**(선택): Pages Functions와 D1을 로컬로 띄운다. 자세한 절차는 [`AGENTS.md`](AGENTS.md) 검증 4번을 본다.
그냥 열거나 정적 서버로 연 경우에도 게임은 돌고, 랭킹만 비어 있다(`file://`로 열면 배포 서버로 기록을 보낸다).

### 왜 ES 모듈이 아닌가
`file://`로 열면 브라우저가 `type="module"` 스크립트를 CORS로 막는다. 그래서 JS는 일반 `<script src>`로 **순서대로** 불러오고, 모든 파일이 전역 스코프 하나를 공유한다.

- 파일 순서 = 의존 방향이다. 앞 파일의 전역을 뒤 파일이 쓴다.
- 로드되자마자 실행되는 최상위 코드는 **앞 파일**에 정의된 것만 쓸 수 있다. 함수 몸체 안의 참조는 순서와 상관없다.
- 최상위 이름이 파일끼리 겹치면 안 된다.
- 새 파일을 만들면 `index.html`의 `<script>` 목록에 의존 순서대로 넣는다. 시뮬레이터도 이 목록을 읽는다.

## 개발 가이드

핵심 규칙만 추렸다. 전체는 [`AGENTS.md`](AGENTS.md)에 있다.

**기술 제약**
- 저장소 안의 파일만으로 완결한다. 외부 스크립트·폰트·이미지·CDN, 빌드 단계를 쓰지 않는다.
- 저장은 `localStorage`만 쓰고 모든 읽기/쓰기를 `try/catch`로 감싼다. 저장이 비었거나 깨져도 정상 동작해야 한다.
- 저장 구조를 바꾸면 키의 버전(`brickquest:run:v*`, `brickquest:meta:v*`, `brickquest:profile:v*`, `brickquest:audio:v*`)을 올리고, 이전 저장은 옮기거나(migration) 안전하게 버린다.
- 게임 결과에 영향을 주는 무작위와 연출용 무작위를 구분한다.

**코드 스타일**
- 주석은 한글로 쓰고, "무엇"이 아니라 "왜"를 적는다.
- 과설계보다 단순함을 우선한다. 클래스·패턴은 실제로 복잡할 때만 쓴다.

**시각 규칙**
- 배경은 베이지 계열이고, 강조색은 화(火) `#C1443C` 하나뿐이다. 붉은색은 항상 "위험"을 뜻한다.
- 색은 CSS 변수로만 정의한다. 캔버스도 `readColors()`로 같은 토큰을 읽는다. 다크 모드를 지원한다.
- 캔버스 논리 해상도는 180×340 도트이고 CSS로 확대한다. 캔버스 안에는 숫자와 아이콘만 그리고, 한글은 DOM에 둔다.
- 그라디언트·보라색·과장된 그림자는 쓰지 않는다. 모바일 우선이고, 탭 타겟은 44px 이상이다.
- **설명서 없이 읽히는 게임**을 지향한다. 새 요소는 튜토리얼 문장 대신 아이콘·연출·색으로 전달한다.

**밸런스 목표**(조준 봇 기준)
- 1세션 돌파율 30~40%
- 보스를 잡은 순간 남은 체력 중앙값 20~30%. 이기는 판은 대부분 아슬아슬해야 한다.
- 숫자 인플레이션 금지. 성장은 구슬·유물로만 한다.

## 검증: 문법·밸런스·브라우저

변경 후에는 최소한 1~2번을 돌린다.

**1. 문법 검사**
```bash
for f in js/*.js; do node --check "$f" || echo "실패: $f"; done
```

**2. 밸런스 시뮬레이션**
```bash
node tools/sim.mjs 60    # 인자 = 원정 횟수(기본 60)
```
`index.html`이 불러오는 JS를 가짜 DOM 위에서 돌린다. "조준 봇"이 원정을 끝까지 플레이하고 돌파율과 남은 체력 분포를 출력한다.
- 결과는 실행마다 ±10%p 흔들린다. 비교할 때는 60회 이상으로 돌린다.
- 봇은 사람보다 약하다. 절댓값보다 **변경 전후 비교**에 쓴다.
- 게임 코드에서 훅을 거는 줄이 바뀌면 "훅 삽입 실패"로 멈춘다. 그때는 `tools/sim.mjs`의 `HOOK_*`를 새 코드에 맞게 고친다.

**3. 실제 브라우저**
`index.html`을 `file://`로 연다. 메인 → 지도 → 전투 → 보상 → 새로고침 후 이어하기까지 해 보고 콘솔 오류를 확인한다. 로드 순서나 전역 이름 충돌 문제는 여기서만 드러난다. Playwright로 자동화해도 된다.

### 에셋 이미지 내보내기
게임 코드(`js/sprites.js`의 `SPR`·`ICON`·`FONT`·`drawOrbSprite`, `css/style.css`의 색 토큰)를 그대로 읽어 PNG·GIF로 뽑는다. 도트를 고쳤으면 다시 돌리기만 하면 된다. 게임 실행에는 필요 없는 개발 도구다(Python 3 + Pillow).
```bash
pip install pillow
python3 tools/export_assets.py                  # docs/assets/light
python3 tools/export_assets.py --theme both     # 라이트·다크
python3 tools/export_assets.py --only static,fx --scale 4
```
- 정적: 스프라이트(기본·정예·피격 변형), 아이콘, 구슬, 숫자 폰트, 로고, 한 장 모음(`contact_sheet.png`)
- 연출 GIF: 몬스터별 공격·피격·쓰러짐, 보스 분노, 벽돌 종류별 파괴, 폭탄 폭발, 구슬별 대기 연출, 전투 한 판 재현(`battle.gif`)
- 연출은 `battle.js`의 공식(파편·숫자 팝업·포물선 탄·돌진·물리)을 옮겨 재현한다. 충격파 링·히트스톱·슬로모션·대기 동작은 **툴 전용 제안**으로, 게임에는 아직 없다.
- 미리보기: [`docs/assets/README.md`](docs/assets/README.md)

## 배포

정적 파일이라 폴더를 그대로 올리면 된다. 현재는 **Cloudflare Pages**가 GitHub 저장소와 연결돼 있다.

| 항목 | 값 |
|---|---|
| 프로덕션 주소 | https://brick-crawl.pages.dev |
| 프로덕션 브랜치 | `main` (푸시하면 자동 배포) |
| 미리보기 | 다른 브랜치·PR마다 별도 주소 자동 생성 |
| 프레임워크 프리셋 | None |
| 빌드 명령 | 없음 |
| 출력 디렉터리 | `/` (저장소 루트) |
| Functions | `functions/` (기록 API) |
| D1 바인딩 | `DB` → `brick-crawl` (Production) |

새 환경에 기록 서버를 붙이려면 D1 데이터베이스를 만들고 `db/schema.sql`을 실행한 뒤, Pages 프로젝트 설정 → Bindings에서 D1을 `DB`라는 이름으로 연결한다.

GitHub Pages, Netlify 같은 다른 정적 호스팅에도 올릴 수 있다. 이때는 기록 서버가 없으니 랭킹만 비어 있다.

## AI 에이전트와 함께 작업하기

이 저장소는 AI 코딩 에이전트와 함께 개발한다. 에이전트마다 지침 파일을 따로 두면 내용이 어긋나기 쉬워서, **원본은 하나**만 둔다.

| 파일 | 역할 |
|---|---|
| [`AGENTS.md`](AGENTS.md) | **공통 지침의 원본.** 응답 규칙, 기술 제약, 파일별 담당, 코드·UI 규칙, 검증 방법, 밸런스 목표 |
| [`CLAUDE.md`](CLAUDE.md) | Claude Code 진입점. `@AGENTS.md`로 원본을 불러오기만 한다 |
| [`docs/GAME_DESIGN.md`](docs/GAME_DESIGN.md) | 현재 구현 기준의 규칙·수치·설계 이유 |
| [`docs/tasks/`](docs/tasks/) | 작업 지시서. 하나씩 집어 진행한다 |

`AGENTS.md`를 자동으로 읽는 도구(Codex, Cursor, GitHub Copilot 등)는 별도 설정 없이 쓰면 된다. 자동으로 읽지 않는 도구라면 작업을 시작할 때 "`AGENTS.md`를 먼저 읽어라"라고 지시한다.

에이전트에게 맡길 때 특히 지켜야 할 점은 다음과 같다.
- 재미·난이도에 영향을 주는 기획 판단은 에이전트가 임의로 정하지 않는다. 선택지를 정리해 사람에게 묻는다.
- 수치 미세 조정은 시뮬레이터로 근거를 만든 뒤에만 진행한다.
- 변경 후에는 문법 검사와 시뮬레이터 결과를 보고에 포함한다.

## 기여하기

이슈와 PR 모두 환영한다.

1. `main`에서 브랜치를 만든다.
2. [`AGENTS.md`](AGENTS.md)의 규칙대로 작업한다. 사람이든 에이전트든 같은 규칙을 따른다.
3. 검증 1~2(문법·시뮬레이터)를 돌리고, 밸런스에 영향이 있으면 PR 본문에 전후 수치를 적는다.
4. 커밋은 기능 단위로 작게 나누고, 메시지는 한글로 "무엇을 왜" 적는다.
5. PR을 올리면 Cloudflare Pages 미리보기 주소에서 바로 플레이해 볼 수 있다.

큰 기획 변경(새 시스템, 난이도 곡선 변경)은 먼저 이슈로 방향을 맞춘다.
