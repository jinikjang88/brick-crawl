## 범위와 판단 기준

## R01 — 불굴 피해 감소가 재생에 연결됨

관련: [battle.js](../../js/battle.js)의 hurtPlayer(), [data.js](../../js/data.js)의 TREE, [screens.js](../../js/screens.js)의 battleEnd().

- 데이터에서 d3는 재생(승리 시 체력 +2, 비용 3), d4는 불굴(몬스터·붕괴 피해 ×0.75, 비용 8)이다.
- hurtPlayer()는 tree('d3')를 검사해 피해를 감소시킨다. 재생은 회복과 피해 감소를 함께 주고, 선행 노드를 이미 찍은 상태에서 불굴을 사도 추가 효과가 없다.
- 재현: 방어도 0·체력 24에서 피해 8을 적용한다. d3만 활성화하면 피해 6, d4만 활성화하면 피해 8이다. 단독 활성화는 원인 분리를 위한 테스트 상태이며 정상 UI에서는 d4에 선행 조건이 있다.
- 수정: 감소 조건을 d4로 연결한다. 승리 회복의 d3 조건은 유지한다. 독 피해는 현재 별도 경로이므로 불굴의 설명 범위(몬스터·붕괴)와 일치하는지 확인한다.

완료 기준:
- [x] 재생만 있으면 피해 8, 승리 회복 +2.
- [x] 정상 선행 조건을 포함한 불굴 계정은 피해 8 → 6.
- [x] 방어도 흡수 전 감소와 올림 규칙을 유지하고 몬스터·붕괴 모두 확인. (독은 별도 경로라 불굴 대상이 아니다. 설명 "몬스터·붕괴 피해"와 일치)
- [x] 트리 없음/본편 조합 계정의 밸런스를 별도로 비교. 시드 20261006, 60회, 수정 전후 동일: 트리 없음 1층 25%·보스 체력 42%, SIM_TREE=main 98%·69%(완주 10%), all 100%·92%(완주 62%). 시뮬레이터 조합은 d3·d4를 함께 찍어 영향이 없고, 재생만 찍고 불굴을 안 찍은 계정만 피해 감소를 잃는다.

## R02 — 손상된 저장이 시작 화면을 막음

관련: [save.js](../../js/save.js)의 loadRun()/loadMeta(), [profile.js](../../js/profile.js)의 loadProfile(), [screens.js](../../js/screens.js)의 showMain()/resumeRun().

- loadRun()은 v=2, deck 배열, map 배열 길이 5만 확인한다. relics, hp, maxHp, path, 위치, 지도 노드, 구슬 ID 등 사용 시 필요한 값은 검사하지 않는다.
- 재현 데이터: {"v":2,"deck":["basic"],"map":[[],[],[],[],[]]}.
- 해당 데이터가 loadRun()을 통과하고 showMain()에서 newBattle()을 실행하다 relics.whetstone 접근 예외가 발생했다. 이어하기를 누르기 전부터 메인이 막힌다.
- 프로필도 id/name의 문자열 여부만 확인한다. queue:null 같은 값은 기본 queue를 덮어써 후속 some()/length 접근에 문제가 생길 수 있다. 이 부분은 추가 재현 대상이다.
- 수정: 로딩 경계에서 필수 필드·유효 ID·수치 범위·지도 연결을 검증한다. 호환 가능한 추가 필드는 기본값으로 보완하고, 복구 불가능한 원정은 안전하게 거부한다. JSON 파싱 성공만으로 유효한 저장으로 판단하지 않는다.
- 메타의 best/pts/tree/badges/seen과 프로필 대기열 항목도 같은 원칙으로 점검한다. 원정이 깨져도 정상 메타와 프로필은 보존한다. 저장 구조를 바꾸면 버전 및 이전 정책을 함께 명시한다.

완료 기준:
- [x] 빈 저장, 깨진 JSON, 필수 필드 누락, 잘못된 타입에서 메인이 정상 표시됨.
- [x] 알 수 없는 구슬·유물, 빈 덱, 잘못된 pending/pos/지도 연결을 안전하게 처리.
- [x] 정상 기존 저장의 보상·상점·전투 이어하기 유지.
- [x] localStorage 읽기·쓰기 예외에서도 새 게임 가능.
- [x] 잘못된 프로필 대기열 때문에 게임 종료 처리가 중단되지 않음.

처리 결과(save.js `fixRun()`): 지도(5줄·칸·연결·보스)와 덱(유효 구슬 1개 이상)이 깨지면 원정을 버리고, 나머지(사라진 구슬·유물 id, 범위 밖 체력·코인, 잘못된 위치·대기 칸·경로, 보상 후보·상점 진열)는 기본값으로 메워 이어한다. 메타는 버리지 않고 깨진 수치·객체만 기본값으로 메운다. 프로필 대기열은 형식이 맞는 항목만 남긴다. 저장 구조 자체는 바뀌지 않아 키 버전은 그대로다.

## R03 — 원정 기록과 최고 기록 집계의 비원자적 처리

관련: [기록 API](../../functions/api/[[path]].js)의 record(), [DB 스키마](../../db/schema.sql).

1. runs INSERT OR IGNORE가 성공한다.
2. players의 runs/best/best_at UPDATE가 일시 오류로 실패한다.
3. 클라이언트가 같은 rid로 재전송한다.
4. INSERT가 중복으로 판정되어 ok:true, dup:true를 반환한다. UPDATE는 재실행되지 않는다.

모의 DB에서 첫 요청의 UPDATE 실패 후 재요청이 성공·중복 응답을 반환하고, UPDATE 시도 횟수는 1로 남는 것을 확인했다. 서버에 원정 행은 있지만 최고 기록과 원정 횟수가 반영되지 않고 클라이언트 대기열에서도 제거될 수 있다.

수정 방향: 실제 D1에서 지원하는 원자적 실행 방법을 공식 문서로 확인해 삽입과 집계를 함께 처리하는 방식을 우선 검토한다. 대안은 원정 기록에서 집계를 복원하는 멱등 처리다. 중복 요청마다 runs를 증가시키는 단순 재실행은 금지한다. 이미 불일치한 데이터의 복구는 별도 운영 작업으로 범위와 대상을 정한다.

완료 기준:
- [ ] 삽입 후 집계 단계 실패를 주입해 재시도 시 일관성이 회복됨.
- [ ] 동일 rid 순차·동시 재전송이 원정 횟수를 중복 증가시키지 않음.
- [ ] 최고 기록·동점 시각 규칙 유지.
- [ ] 로컬 Functions+D1에서 통합 검증. 실제 사용자 기록으로 시험하지 않음.

- 파쇄기는 가장 아래 벽돌을 dead=true로 만들고 onBreak()를 호출한다.

- 재현: 체력 24, 파쇄기 보유, 2턴 하강 직전 r=10의 일반 벽돌 한 개. 하강 후 r=11 벽돌을 파쇄하지만 붕괴 피해 2까지 받아 체력이 22가 된다.
- 수정: 붕괴 피해 목록에서 이미 파괴된 벽돌을 제외한다. 다른 파괴 경로에서도 같은 벽돌의 효과가 중복 실행되지 않는지 확인한다.

완료 기준:

## R05 — 미전송 기록 보존과 재시도 분류

관련: [net.js](../../js/net.js)의 recordRun()/doFlush()/api(), [profile.js](../../js/profile.js).

- doFlush()는 네트워크 실패와 5xx만 보존하고 다른 응답은 queue.shift()로 버린다. 429 같은 일시적 제한도 삭제 대상이다. 현재 API가 429를 직접 생성하지 않더라도 앞단 제한 응답을 받을 수 있다.
- 등록 여부를 로컬에서 true로 기억한 뒤 서버에서 플레이어가 사라지면 record의 404도 복구 없이 버린다.
- 대기열이 50개를 넘으면 slice(-50)으로 오래된 미전송 기록을 제거한다. 최고 기록이 이 구간에 있으면 서버에 반영되지 않는다.
- 수정: 성공, 영구적인 형식 오류, 재시도 가능한 실패를 분류한다. 플레이어 미등록은 재등록 후 재시도하고, 일시 실패에는 대기열을 보존한다. 무한 재시도 루프와 동시에 여러 flush가 실행되는 상황을 방지한다.
- 대기열 저장 한도는 기획·운영 결정이 필요하다. 전체 원정 횟수를 보존할지, 집계 모델을 바꿔 압축할지 결정해야 한다. 최고 기록만 남기면 서버의 원정 횟수 의미가 달라지므로 임의 변경하지 않는다.

완료 기준:
- [ ] 네트워크 실패·5xx·429 이후 대기열 유지 및 성공 후 한 번만 제거.
- [ ] 형식 오류는 무한 반복 없이 처리하고 다음 정상 항목 전송 가능.
- [ ] 50개 초과 오프라인 기록의 보존 정책을 문서화하고 최고 기록 손실 방지.
- [ ] 서버 없는 환경에서도 게임 플레이와 결과 화면이 정상 동작.

## R06 — 게임용 시드 RNG 도입 및 연출 분리

관련: [config.js](../../js/config.js), [map.js](../../js/map.js), [battle.js](../../js/battle.js), [rewards.js](../../js/rewards.js), [screens.js](../../js/screens.js), [sim.mjs](../../tools/sim.mjs), [작업 01](01-final-boss.md).

- rnd/pickW, 지도 연결, 벽돌 생성, 조준 초기화, 강화 성공 등에 Math.random()을 사용한다. 파티클도 같은 난수원을 사용한다.
- 시뮬레이터는 Math.random을 시드 함수로 통째로 교체한다. 재현 시드는 있지만 게임 저장의 시드 RNG 구현은 아니다. 파티클 수 변경으로 난수 소비 순서가 바뀌면 이후 지도·보상·전투 결과도 바뀔 수 있다.
- 수정: 원정 시드와 필요한 스트림 상태를 저장하고 게임 결과용 난수를 명시적으로 호출한다. 지도·전투·보상 스트림 분리는 작업 01의 요구와 함께 검토한다. 닉네임·연출은 결과용 스트림을 소비하지 않는다.
- 전투 재시작 시 같은 판을 재구성하는 시점, 보상 후보 저장, 강화 결과의 저장 경계를 정의한다. 저장 이전 정책은 최신 5층 구조에 맞춰 다시 정한다.

완료 기준:
- [ ] 같은 시드와 같은 입력으로 지도·첫 전투·보상을 재현.
- [ ] 파티클 수·이미지 연출 변경이 게임 결과를 바꾸지 않음.
- [ ] 저장 후 이어하기와 중단 없는 실행의 결과가 정의한 경계에서 일치.
- [ ] Node 시뮬레이션에서 기록 통신 비활성 유지.

## R08 — 스킬 트리 탭 영역
