# 작업 08 — 부품 파밍과 구슬 조립 (초안)

상태: **초안 · 소유자 검토 대기**(2026-11-05). 결정된 것: 구슬 보상을 부품 3택1로 대체(A), 조립은 윤의 정비소에서만, 히든 구슬 4종, 모듈 점수 이름은 "부품" → **설계도**.
아래 수치·레시피·히든 효과는 제안이다. 승인 뒤 구현하고 시뮬레이터로 1세션 돌파율 20~30%를 다시 맞춘다.

## 1. 흐름

| 때 | 지금 | 바뀐 뒤 |
|---|---|---|
| 일반 전투 승리 | 크레딧만 | 크레딧 + **그 기체의 부품 1개** |
| 정예 승리 | 칩 3택1 → 구슬 3택1 | 칩 3택1 → **부품 3택1**(그 기체 부품 1개 확정 + 무작위 2) |
| 보스 승리 | 칩 3택1 → 구슬 3택1 | 칩 3택1 → **부품 3택1**(그 보스의 코어 확정 + 무작위 2) |
| 윤의 정비소 | 구슬 2·칩 1·복구 패치·강화·빼기 | 그대로 + **조립하기**(무료, 방문마다 횟수 제한 없음) |

- 부품은 침투 안에서만 가진다(침투가 끝나면 사라진다). **적재함 6칸**, 넘치면 버릴 부품을 고른다.
- 조립 = 큐의 구슬 1개 + 부품 1개 → 다른 구슬. **강화 단계(+)는 그대로 옮긴다**(강화한 보람이 사라지지 않게).
- 부품이 떨어지는 결과는 원정 시드 흐름 `rand('reward')`로 정한다(새로고침으로 바뀌지 않음).
- 다시 스캔하기·모듈 "부품 감별"(후보 +1)은 부품 3택1에 그대로 적용한다.
- 심층부: 기체는 같은 부품, 심층부 보스는 보스 코어 4종 중 무작위.

## 2. 부품 8종

| 부품 | 얻는 곳 | 성격 |
|---|---|---|
| 나노 젤 | 나노 슬러지 | 회복·흡수 |
| 광학 렌즈 | 경비 드론 | 궤적·갈래 |
| 장갑판 | 방벽 가디언 | 방어·반사 |
| 부식 캡슐 | 오염 살포기 | 독·분해 |
| 센티넬 축전기 | 1층 보스 | 폭발·충격 (대본 C1-BOSS-OUT) |
| 코테크 집속 회로 | 2층 보스 | 관통·연산 (C2-BOSS-OUT) |
| 제미디 분열 렌즈 | 3층 보스 | 분광 (C3-BOSS-OUT) |
| 클라드 안전 코어 | 4층 보스 | 과전류 (C4-BOSS-OUT) |

보스 코어 + 번개 구슬 = 대본에서 그 보스가 준 구슬(EMP·관통·프리즘·아크). **이것으로 D3(보스 첫 처치 해금)을 대신한다.** 아크 구슬의 트로피 잠김("원샷")은 풀고, 클라드 안전 코어로 얻게 한다.

- 정비소 구매 목록에는 계속 무작위 구슬 2개가 나온다(부품이 안 맞을 때의 출구).

## 4. 히든 구슬 4종 (조립으로만, 보상·정비소 구매에 나오지 않음)

효과는 규칙을 비트는 것만 두고, 수치를 곱하지 않는다(AGENTS 숫자 인플레이션 금지). 수치는 시뮬레이터로 조정한다.

| 이름 | 레시피 | 효과(초안) | 대본 근거 |
|---|---|---|---|
| 교대 신호 | 차폐 + 센티넬 축전기 | 쏜 턴에 기체의 첫 공격을 막고, 막은 피해만큼 데이터 벽 맨 아래 줄 벽돌을 부순다 | 센티넬 "교대… 요청…" |
| 방화문 | 관통 + 코테크 집속 회로 | 이번 턴 데이터 벽이 내려오지 않는다(전투마다 1번) + 벽돌 3개 관통 | 코테크가 방화문을 열어 준다 |
| 환풍기 | 전자석 + 제미디 분열 렌즈 | 세 번째 발사마다(세 박자) 이 구슬의 천장 타격 상한 +2 | 세 박자마다 철컥거리는 환풍기 |
| 마지막 번개 | 아크 + 제미디 분열 렌즈 | 모든 벽돌을 뚫고 천장을 친 뒤 세 갈래로 갈라져 내려온다(갈래 피해 ÷3) | 제목·숨겨진 트랙 00_LAST_ARC |

- 마지막 번개는 3층 보스의 렌즈를 4층 보스 뒤까지 아껴야 만들 수 있다(적재함 운용이 퍼즐이 된다).
- 처음 만든 순간 레시피가 아카이브에 영구로 남는다. 아직 못 찾은 히든은 "??? = 차폐 + ?"처럼 재료 하나만 보여 준다.

## 5. 화면

- 부품 3택1 카드: 부품 그림 + 이름 + "이 부품으로 만들 수 있는 구슬" 한 줄(지금 큐 기준).
- 정비소 "조립하기": 큐의 구슬을 고르면 가진 부품으로 만들 수 있는 결과가 카드로 뜬다. 결과 카드에 전·후 효과를 나란히.
- 헤더 구슬 줄 옆에 적재함 칸 수(예: 부품 4/6). 지도 부제에도 같은 숫자.
- 부품 그림 8종은 `docs/ASSET_PROMPTS.md`에 프롬프트를 더한다. 그림이 오기 전에는 도트 아이콘으로 대신한다.

## 6. 바뀌는 이름 (GLOSSARY)

- 파밍하는 물건 = **부품**, 넣어 두는 곳 = **적재함**, 동작 = **조립하기**.
- 모듈 설치 점수: 부품 → **설계도**("설계도 +1 · 첫 돌파", "설치하기 (설계도 3)").
- 모듈 "예비 부품"(무작위 칩 하나로 출발)은 이름이 겹쳐 **예비 칩**으로 바꾼다.

## 7. 구현 범위와 위험

- 데이터: `PARTS`, `RECIPES`, `HIDDEN`(js/data.js). 히든 구슬 4종은 `ORBS`에 `hidden:true`로 더해 보상 풀에서 뺀다.
- 저장: 원정 `brickquest:run:v4` → v5(`parts` 추가, 옛 저장은 빈 적재함으로 옮김). 메타 `recipes`(찾은 레시피) 추가, 없으면 빈 값.
- 보상: `rollOrbs` 자리를 `rollParts`로. 시뮬레이터 봇에 조립 정책(가장 높은 등급 결과를 고름)을 넣는다.
- 회귀 검사: 시드 고정 드롭, 레시피 결과, 강화 단계 유지, 적재함 넘침, v4 저장 이전, 히든 첫 조립 기록.
- 위험: 구슬을 원하는 대로 만들 수 있어 지금보다 쉬워질 수 있다 → 적재함 크기·부품 드롭률로 맞춘다(시뮬레이터 60회 이상 비교).
