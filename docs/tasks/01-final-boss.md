# 작업 01: 3세션 구조 + 최종 보스 + 엔딩 + 시드 RNG (브릭 크롤)

## 배경
지금은 세션이 끝없이 이어져 원정의 끝이 패배뿐이다. 엔드게임 방향은 아래 3단계로 정했다.
1. **(이번 작업)** 원정을 3세션으로 고정하고, 3세션 보스를 최종 보스로. 깨면 엔딩.
2. 고난 단계: 클리어 후 해금, 단계마다 규칙 하나 추가(숫자 인플레이션 없이 어려워짐).
3. 일일 도전 + 랭킹: 모두 같은 시드로 한 판. Cloudflare Worker + D1.

이번 작업에서 3단계를 위한 **시드 RNG를 미리 깔아 둔다.** 나중에 한꺼번에 바꾸면 범위가 너무 커진다.

## 요구사항

### A. 시드 RNG
- 게임 결과에 영향을 주는 모든 무작위를 시드 기반 PRNG로 교체한다.
  - 대상: 지도 생성, 노드의 몬스터 선택, 벽돌 줄 생성, 소환 위치, 덱 섞기, 보상·상점 뽑기, 코인 획득량, 조준선 시작 위치·방향.
  - 제외: 파티클·흔들림 등 연출(그대로 Math.random).
- 같은 시드면 같은 지도·같은 벽돌 배치가 나와야 한다. 단, 플레이어 선택(경로, 보상)에 따라 갈라지는 건 정상.
  - 권장: 용도별로 스트림을 분리한다(예: map, wall, loot). 벽돌 스트림은 (시드, 세션, 칸, 턴)으로 파생해서, 다른 선택을 해도 같은 칸에서는 같은 벽돌이 나오게 한다. 이유: 일일 도전에서 공정한 비교가 되려면 같은 전투는 같은 판이어야 한다.
- 시드는 원정 생성 시 정하고 `RUN.seed`에 저장한다. 메인 화면에서 시드를 입력해 시작하는 기능은 **이번에는 넣지 않는다**(3단계에서).
- 저장 버전을 v3으로 올리고, v2 저장은 안전하게 버린다(이어하기 버튼에서 사라지게). 메타(`brickquest:meta`)는 v2를 그대로 읽어 이어 쓴다.

### B. 3세션 구조
- 세션 3의 보스 노드는 최종 보스. 세션 1·2 보스는 지금의 "탑의 주인" 유지.
- 최종 보스를 이기면 다음 세션으로 가지 않고 엔딩.

### C. 최종 보스 (기획 초안, 수치는 시뮬레이터로 조정)
- 이름(가제): **성벽의 왕**. 스프라이트는 16×16 도트, 기존 보스보다 위압적으로.
- 컨셉: **숫자가 아니라 규칙을 비트는 보스.** 이 게임의 핵심인 "천장 타격"을 방해한다.
- 1페이즈: 천장 7칸 중 2칸이 **봉인**된다. 봉인 구간에 닿은 구슬은 튕기기만 하고 타격이 들어가지 않는다.
  - 표시: 천장 선 위에 봉인 구간을 빗금(ink 계열)으로. 말로 설명하지 않아도 "저기는 막혔다"가 보여야 한다.
- 2페이즈(체력 절반): 봉인 구간이 **매 턴 한 칸씩 옆으로 이동**한다. 다음 턴 봉인 위치를 예고(행동 예고처럼).
- 행동 패턴은 기존 행동(n턴 연속 공격·방어·독·소환·대기)을 조합. 공격은 배율 없이 턴 수로만 세기를 조절한다(`GAME_DESIGN.md` 몬스터 절). 새 행동이 필요하면 아이콘을 추가한다.
- 기획 판단이 갈리는 부분(봉인 칸 수, 이동 방식, 패턴)은 구현 전에 선택지를 정리해 물어봐도 된다.

### D. 엔딩
- 최종 보스 격파 연출 후 엔딩 화면: "원정 완료", 걸린 총 턴 수, 남은 체력, 최종 덱, 유물 목록.
- 메타에 클리어 횟수(`clears`)와 최고 기록을 남긴다. 메인 화면 기록 줄에 "원정 완료 N회" 표시.
- 버튼: 새 원정, 메인 화면. (고난 단계 해금 문구는 2단계에서.)
- 저장된 원정은 엔딩 후 삭제.

### E. 지도 표시
- 지도 제목에 "세션 2 / 3"처럼 남은 거리를 보여준다.
- 세션 3의 보스 노드는 "최종"으로 표기하고 강조색 테두리.

## 하지 말 것

## 기존 기록 서버와 맞출 점 (작업 01 이후 추가된 기능)
- 원정 기록은 끝날 때 `recordRun(RUN)`으로 올린다(지금: 쓰러짐·포기·저장 덮어쓰기). **엔딩에서도 `clearRun()` 전에 `recordRun`을 불러야** 클리어가 랭킹에 남는다.
- 클리어 기록 값: `runProgress`로 세면 `2×5 + 5 = 15`가 최대다. 클리어를 "15칸 도달"과 구분할지(예: 클리어 시 16) 정한다 — 랭킹 의미가 걸린 기획 판단이라 구현 전에 묻는다.
- `MAX_PROGRESS`(200)는 "세션이 끝없이 이어진다"는 전제의 상한이다. 3세션 고정이면 실제 최댓값으로 낮춰 조작 여지를 줄인다.
- v2 저장을 버릴 때 그 원정 기록이 사라지지 않게, 버리기 전에 `recordRun`으로 올려 둔다(`rid`가 있어 중복 집계되지 않는다). v3 원정도 `rid`를 유지한다.

- [ ] 같은 시드로 원정을 두 번 시작했을 때 1세션 지도와 첫 전투 벽돌 배치가 같음(검증 방법을 보고에 포함).
- [ ] 세션 3 보스를 이기면 엔딩이 나오고, 메타에 클리어가 기록되며, 기록 서버 대기열에 클리어 기록이 들어가고, 저장이 지워진다.
- [ ] v2 저장이 있는 상태로 열어도 오류 없이 메인 화면이 뜬다.
- [ ] `tools/sim.mjs`가 새 구조에서 돌아간다(필요하면 봇이 엔딩을 인식하도록 수정). 지표 보고:

  - 최종 보스 격파 시 남은 체력 중앙값 20~30%
- [ ] 변경 요약, 시뮬레이션 수치, 남은 문제를 한글로 보고.
